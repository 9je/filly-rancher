# Slice R3 -- Feel Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make moving, penning and building FEEL right -- the tail stops streaming and leading, the hoofsteps land on the animation's own footfalls instead of on a distance counter, one press of E pens a pony, a refused press says so once and softly, and a paddock's legal spot is something you can see before you commit rather than something you find by trial and error.

**Architecture:** Four independent seams, none of which touches `game/systems/` except one sanctioned constant. (1) The hair spring simulator gains a speed-aware `influence`: `game/scripts/pony_rig.gd` grows `influence_for_speed()` and `hair_simulator()`, and `game/actors/player/player.gd` drives it once per physics frame from the ground speed it already computes -- at a standstill and at a sneak the hair is exactly as free as it is today (every existing measurement stays bit-identical), and at the run it is pinned back toward the rig so it cannot fly. (2) The hoofstep accumulator stops counting metres and starts watching the locomotion clip's own playback position, firing once per cycle at the same phase every time. (3) `game/world/interaction.gd` puts `PLOT_BUILD` and `PEN_MOVE_IN` in one tier settled by distance, so standing at a built pen's gate no longer hands E to the empty plot 20 cm further away; `game/world/ranch.gd` grows one debounced `_deny()` funnel that every refusal goes through. (4) `game/world/plot_slot.gd` grows `placement_check()` and a live green/red ghost on the footprint, and its always-on marker boards learn to fade with distance so four marked plots plus a real fence stop reading as a thicket of parallel lines.

**Tech Stack:** Godot 4.5.2 (GDScript), GUT 9.5.0, xvfb for rendered evidence, `tools/bin/godot` headless for every gate.

**Spec:** `docs/superpowers/specs/2026-09-04-presentation-redesign-design.md` (section 6 is this slice; sections 1-2 bind globally; acceptance items 4, 8 and 9 are the bar). The sound-mix bullet of section 6 already shipped with R1 and is NOT in scope here.

**The number that matters is `stiffness=4.33`.** `docs/notes-hair-sim.md` section 11.1 established that Godot's spring solver pulls a joint's tail back toward its rest direction by `stiffness * delta`, an absolute displacement, so the configured stiffness IS a restoring speed in metres per second, and a chain only holds its shape while that speed comfortably exceeds how fast its anchor is being dragged through the world. The player's default travel speed is `Player.RUN_SPEED` = **5.2 m/s**. Her tail's restoring speed is **4.33 m/s** and her six mane locks' is **3.70 m/s** -- both BELOW the speed she moves at, all day, by default. Section 11.1's own margin rule is 2x to 5x the fastest the player can move. That is the whole of "my characters tail is glitching out a lot as i move", and it is why no gate caught it: `hair_lag_test` travels at `TRAVEL_SPEED` = 0.66 m/s, one eighth of the speed the game is played at.

`Tail3`'s configured 4.33 divided by the tail profile's 14.0 gives its mean segment length: **0.3093 m** (4 joints, so `span_factor` is 1.0). The six mane locks' 3.70 over the forelock profile's 10.0 gives **0.370 m** (1 joint each).

- [ ] **Step 2: Write the failing test for the speed rule**

Create `game/test/test_pony_rig.gd`:

```gdscript
extends GutTest
## HOW FREE THE HAIR IS ALLOWED TO BE AT THE SPEED SHE IS ACTUALLY MOVING.
##
## docs/notes-hair-sim.md section 11.1: Godot's spring solver pulls a joint's tail back
## toward its rest direction by `stiffness * delta`, an absolute displacement, so the
## configured stiffness IS a restoring speed in metres per second. A chain holds its shape
## only while that speed comfortably exceeds how fast its anchor is dragged through the
## world. The player's own rig runs its tail at 4.33 m/s and its mane locks at 3.70 m/s,
## measured, while Player.RUN_SPEED is 5.2 -- so at the default travel speed the hair has
## no authority at all and streams. Raising the profiles is not the way out: the same
## profiles are certified on Twilight at walking pace and would go rigid.
##
## So the simulator's `influence` is made a function of ground speed instead. Standing
## still and creeping keep exactly the hair that shipped; running pins it back toward the
## rig it hangs off.

const PonyRigScript := preload("res://scripts/pony_rig.gd")
const PlayerScript := preload("res://actors/player/player.gd")


func test_a_standing_pony_keeps_all_of_her_hair() -> void:
	assert_almost_eq(PonyRigScript.influence_for_speed(0.0), 1.0, 0.0001,
		"nothing is dragging the anchor, so nothing needs pinning")


func test_the_creep_costs_no_follow_through() -> void:
	# SNEAK_SPEED is the speed a player CHOOSES in order to be quiet and to look at things.
	# Every certified hair measurement in docs/notes-hair-sim.md was taken at or below it.
	assert_almost_eq(PonyRigScript.influence_for_speed(PlayerScript.SNEAK_SPEED), 1.0, 0.0001,
		"the sneak is inside the band the shipped profiles were tuned for")


func test_the_run_pins_the_hair_back() -> void:
	var at_run: float = PonyRigScript.influence_for_speed(PlayerScript.RUN_SPEED)
	assert_lte(at_run, 0.5,
		"at 5.2 m/s the chains have less restoring speed than the ground they cross")
	assert_gte(at_run, PonyRigScript.PIN_FLOOR,
		"never below the floor -- welded hair is the OTHER half of 'looks off'")


func test_the_hair_is_never_welded_to_the_skull() -> void:
	# docs/notes-hair-sim.md section 1b: a rest-pose track over the simulation is lockstep,
	# and lockstep was half of the original complaint. There is no speed at which the answer
	# is zero.
	var speed := 0.0
	while speed <= 20.0:
		assert_gt(PonyRigScript.influence_for_speed(speed), 0.0,
			"influence went to zero at %.1f m/s" % speed)
		speed += 0.25


func test_it_never_gets_freer_as_she_speeds_up() -> void:
	var previous := PonyRigScript.influence_for_speed(0.0)
	var speed := 0.0
	var samples := 0
	while speed <= 20.0:
		var here: float = PonyRigScript.influence_for_speed(speed)
		assert_lte(here, previous + 0.0001,
			"influence rose between %.2f and %.2f m/s" % [speed - 0.25, speed])
		previous = here
		samples += 1
		speed += 0.25
	assert_gt(samples, 40, "the sweep has to actually walk the range it claims to")


func test_negative_speed_is_read_as_speed() -> void:
	# get_ground_speed() is a length and cannot be negative, but a caller handing a signed
	# axis instead would otherwise get full influence at full reverse.
	assert_almost_eq(PonyRigScript.influence_for_speed(-PlayerScript.RUN_SPEED),
		PonyRigScript.influence_for_speed(PlayerScript.RUN_SPEED), 0.0001)
```

- [ ] **Step 4: Add the speed rule to PonyRig**

In `game/scripts/pony_rig.gd`, immediately after the `SPAN_EXPONENT` block (around line 207) and before `const SIMULATOR_NAME`:

```gdscript
## HOW MUCH OF THE SPRING SOLVE SURVIVES, AS A FUNCTION OF HOW FAST THE ANCHOR IS MOVING.
##
## THE DEFECT. Section 11.1 of docs/notes-hair-sim.md established that `stiffness` is a
## restoring SPEED in metres per second, and that a chain holds its shape only while that
## speed comfortably exceeds how fast its anchor is dragged. Measured on the player's own
## rig (pokeypierce, which is what game/data/hidden/stock_shy.tres names): her tail runs at
## 4.33 m/s and her six mane locks at 3.70 m/s, against a Player.RUN_SPEED of 5.2 m/s that
## is now the DEFAULT travel speed rather than a held button. The hair has no authority at
## the speed the game is played at, and the owner saw exactly that: "my characters tail is
## glitching out a lot as i move".
##
## WHY NOT JUST RAISE THE PROFILES. Because PROFILES is certified on Twilight at 0.66 m/s
## and section 10.4's sweep is explicit that a forelock at the mane's stiffness goes rigid
## (0 ms trail, no follow-through at all). Tripling every profile to buy authority at 5.2
## m/s would kill the follow-through this file exists to provide, on every pony in the
## game, at every speed.
##
## WHY INFLUENCE. `SpringBoneSimulator3D.influence` blends the modifier's output back
## toward the pose the skeleton had before it ran. For hair bones that pose is the REST
## pose, because the exporter deliberately keyframes none of them (section 1b), so lowering
## influence is exactly "pin the hair back toward the rig" -- the spec's own word for the
## fix -- and it is speed-dependent by construction rather than by retuning a spring.
##
## THE BAND. Below SPEED_PIN_START nothing changes at all: a standing pony and a creeping
## one (Player.SNEAK_SPEED is 1.32 m/s) get the same hair that shipped and the same numbers
## every measurement in docs/notes-hair-sim.md was taken at. From there it falls linearly
## to PIN_FLOOR at SPEED_PIN_FULL, which is Player.RUN_SPEED written as a length rather
## than imported, because game/scripts/ must not depend on game/actors/.
##
## PIN_FLOOR IS NOT ZERO AND MUST NEVER BE. Zero influence is the rest pose, which is hair
## welded to the skull -- the other half of the original "looks off" (section 1b). 0.35
## keeps a third of the swing, which reads as hair that follows the body firmly.
const SPEED_PIN_START := 1.5
const SPEED_PIN_FULL := 5.2
const PIN_FLOOR := 0.35


## The simulator influence to hold at `speed` metres per second. Pure: no node, no tree.
static func influence_for_speed(speed: float) -> float:
	var s := absf(speed)
	if s <= SPEED_PIN_START:
		return 1.0
	var t: float = clampf((s - SPEED_PIN_START) / maxf(0.001, SPEED_PIN_FULL - SPEED_PIN_START),
		0.0, 1.0)
	return lerpf(1.0, PIN_FLOOR, t)


## The hair simulator attached to `pony` by attach_hair_simulation(), or null for a model
## that has no hair bones at all. Found by NAME under the skeleton rather than cached by the
## caller, because a body is rebuilt whenever the player changes mane style and a cached
## reference would be pointing at a freed node.
static func hair_simulator(pony: Node3D) -> SpringBoneSimulator3D:
	if pony == null:
		return null
	var skeleton := pony.find_child("Skeleton3D", true, false) as Skeleton3D
	if skeleton == null:
		return null
	return skeleton.get_node_or_null(NodePath(SIMULATOR_NAME)) as SpringBoneSimulator3D
```

```gdscript
## SAY NO ONCE, AND SOFTLY.
##
## Every player-facing refusal in this file goes through here rather than calling _toast()
## directly: one toast, one soft ui_denied, and an identical refusal inside
## DENY_DEBOUNCE_SECONDS is swallowed whole rather than queued behind the line already on
## screen. See DENY_DEBOUNCE_SECONDS for why the window is per message and why it is short.
##
## THE CLOCK IS THE ENGINE'S, NOT THE WORLD'S. Time.get_ticks_msec() rather than the world
## clock, because this is about how fast a thumb moves and not about how fast the sun does;
## a pinned or paused world must not change how a keypress feels.
func _deny(text: String) -> void:
	var now: float = float(Time.get_ticks_msec()) / 1000.0
	if String(_last_denial.get("text", "")) == text \
			and now - float(_last_denial.get("at", -1000.0)) < DENY_DEBOUNCE_SECONDS:
		return
	_last_denial = {"text": text, "at": now}
	_toast(text)
	_sound_call(&"play", [DENY_SOUND])


## The last refusal spoken and the second it was spoken at. For the suite, which otherwise
## has to infer a debounce from a toast queue.
func last_denial() -> Dictionary:
	return _last_denial.duplicate()
```

```gdscript
func placement_check(point: Vector3, radius: float) -> Dictionary:
	if not is_empty():
		return {"ok": false, "reason": "something already stands here"}

## coloured footprint inside a standing fence is the overlapping-frames picture the owner
## already reported once, and the way to not draw it is to not be able to.
func set_ghost(state: int) -> void:
	var wanted: int = Ghost.OFF if not is_empty() else state
	if wanted == _ghost_state:
		return
	_ghost_state = wanted
	if _ghost != null:
		_ghost.queue_free()
		_ghost = null
	if _ghost_state == Ghost.OFF:
		return

	_ghost_box("Floor", Vector3(span, GHOST_HEIGHT, span),
		Vector3(0.0, GHOST_HEIGHT * 0.5, 0.0), mat)
```
